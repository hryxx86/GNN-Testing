### 2.5 Hand-Curated Feature Formula Table (NEW per Codex A-02)

All features computed at end-of-day close on day `t`, with explicit shift to ensure no same-day leakage. Label is 21-day forward c-t-c return at day `t` (so target uses close at day `t+21`).

| Feature | Formula (X_t input) | As-of date | Lookback window | Leakage check |
|---------|--------------------|-----------|---------------- |--------------|
| `hc_ret_mean_5d` | `daily_ret.shift(1).rolling(5).mean()` at day t | end of day t | days [t-5, t-1] | uses only past returns; shift(1) prevents same-day |
| `hc_ret_mean_10d` | `daily_ret.shift(1).rolling(10).mean()` | end of day t | days [t-10, t-1] | same |
| `hc_ret_mean_21d` | `daily_ret.shift(1).rolling(21).mean()` | end of day t | days [t-21, t-1] | same |
| `hc_ret_std_5d` | `daily_ret.shift(1).rolling(5).std()` | end of day t | days [t-5, t-1] | same |
| `hc_ret_std_10d` | `daily_ret.shift(1).rolling(10).std()` | end of day t | days [t-10, t-1] | same |
| `hc_ret_std_21d` | `daily_ret.shift(1).rolling(21).std()` | end of day t | days [t-21, t-1] | same |
| `hc_mom12m` | `(close.shift(21) / close.shift(252)) - 1` | end of day t | days [t-252, t-21] (skip latest month, Jegadeesh & Titman 1993) | uses prices at most t-21 days ago |
| `hc_maxret` | `daily_ret.shift(1).rolling(21).max()` | end of day t | days [t-21, t-1] | uses only past returns |
| `hc_dolvol` | `(close.shift(1) * volume.shift(1)).rolling(21).mean().apply(log)` | end of day t | days [t-21, t-1] | uses past close + past volume |
| `hc_CORR5` | Pearson corr between stock returns and equal-weight sector index returns over `[t-5, t-1]`, sector-mate-of-stock | end of day t | days [t-5, t-1] | only past returns |

**Label**: `fwd_ret_21d = close[t+21] / close[t] - 1`, with cross-sectional z-score per day (winsorized at p1/p99 within day). **Prediction at day t uses features computed at end of day t; label is realized at day t+21.** No information from days >t enters X_t.

`load_data_and_features()` in `run_step3_plan_z_part_a.py:81-138` already implements hc features via `prices.pct_change().shift(1)` pattern; Plan AAA inherits this code path for hc features, only adding 158 Alpha158 columns alongside.

## §3. Methodology

### 3.1 Step 1: Feature Grouping on Pre-experiment Calibration Window (FIXED A-06)

**Calibration window**: first 252 trading days of dataset = approximately 2021-01-29 to 2022-01-29 (indexes [0, 251] in fold_manifest_expanding.json's date array).

**Rationale**: earliest test fold starts at day 796 (per `fold_manifest_expanding.json` fold-0 test=[796, 858]). A 252-day calibration window at the start (days [0, 251]) is strictly before any test fold's evaluation period and any walk-forward train-extension period.

**Procedure**:
1. Slice features (after raw load + per-fold winsor would be incorrect since per-fold winsor depends on each fold's train; for calibration we use a single global per-feature winsor at p1/p99 over days [0, 251] only).
2. Compute Spearman correlation matrix (168×168) on calibration window.
3. Complete-link hierarchical clustering at |ρ|>0.6 (Plan Z++ Part A threshold).
4. Save `groups_168.json` (preregistration artifact). Output filename includes calibration window dates for traceability.

**Sensitivity check (supplementary)**: same clustering computed on fold-0 train slice (Plan Z++ Part A convention) and reported as `groups_168_fold0.json` for cross-reference. Differences flagged in analysis report. If group membership changes substantially (Adjusted Rand Index < 0.85), report concern in paper.

### 3.2 Step 2: Train Production Models (FIXED A-05 + A-11)

**Cell enumeration (corrected from v0; cell_id schema added per Codex 6th-pass)**:
- Architectures: 2 (`arch_idx=0` SAGE-Mean, `arch_idx=1` MLP)
- Seeds: 3 (`seed_idx=0` → 86, `seed_idx=1` → 123, `seed_idx=2` → 456)
- Folds: 5 (`fold_idx=0..4`)
- **Total cells**: 2 × 3 × 5 = **30** (15 per architecture)
- **Globally unique cell_id**: `cell_id = arch_idx * 15 + fold_idx * 3 + seed_idx`, range 0..29
  - This integer is the canonical cell identifier — used as input to `SeedSequence` in §3.3 (NOT the cell_seed value 86/123/456, which would alias across architectures and folds).
  - Stored in audit as `cell_id` column for unambiguous replay (Codex stop-hook 6th-pass fix: `(cell_seed, group_id, date)` triple was non-unique across cells with same cell_seed; `(cell_id, group_id, date)` triple is globally unique).

**Hparams**: locked Stage 0 defaults (lr=1e-3, wd=1e-4, hidden=64, num_layers=2, dropout=0.3, patience=10, epochs=50, optimizer=adam, grad_accum=4).

**Convergence criteria + halt rule (NEW per Codex A-11)**:
- Per cell: training loss must decrease by >1% from epoch 1 to early-stop epoch.
- Per cell: best val IC at any epoch must be > -0.05 (sanity floor; below this suggests catastrophic divergence).
- If >20% of cells (>6 of 30) fail either criterion: halt execution, report to H博士. NO auto-exclusion of failed cells.
- Retries (if needed): same seed + same hparams. NO hyperparameter tuning. Any change requires new labeled plan version.

### 3.3 Step 3: Grouped Permutation Δ-IC Inference (FIXED A-03 + A-08)

**For each trained model and each group**, replicate `compute_grouped_permutation_ic()` from `run_step3_plan_z_part_a.py:477-497` with the SHARED ROW PERMUTATION semantic made explicit:

```python
def grouped_permutation_ic(model, features_t, ..., test_days, group, cell_id, group_id,
                            cell_seed, arch_label, fold_idx, seed_idx):
    """All columns in `group` get the SAME row-permutation per test day.

    Codex Round A verified at run_step3_plan_z_part_a.py:494-497:
        x[:, grp_indices_t] = x[perm][:, grp_indices_t]
    decomposes as: x[perm] permutes ROWS of full panel by `perm`,
    then [:, grp_indices_t] selects only group columns, then assigns back.
    All group columns share the same per-day stock-level permutation.

    Seed inputs (Codex stop-hook 6th pass fix):
    - `cell_id` (0..29): GLOBALLY UNIQUE integer per cell, = arch_idx*15 + fold_idx*3 + seed_idx
    - `group_id` (0..K-1): stable integer from groups_168.json
    - `d` (test date index): trading-day index
    Triple (cell_id, group_id, date) is unique across all 30 × K × N_dates records.
    `cell_seed` (86/123/456) is decorative only — NOT used in seed derivation
    (would alias across architectures and folds with same seed_idx).
    """
    grp_indices = [feat_idx[m] for m in group['members']]
    grp_indices_t = torch.as_tensor(grp_indices, dtype=torch.long)
    permuted_preds = np.zeros((len(test_days), num_stocks), dtype=np.float32)
    with torch.no_grad():
        for i, d in enumerate(test_days):
            # Pass SeedSequence directly to default_rng — uses full 128-bit PCG64
            # entropy via SHA256 internal mixing, no uint32 truncation. The input
            # triple [cell_id, group_id, date] IS the truth source for replay.
            # (Codex 5th pass: generate_state(1) returns uint32, replaced with direct
            # SeedSequence pass; Codex 6th pass: cell_seed → cell_id for uniqueness.)
            ss = np.random.SeedSequence([int(cell_id), int(group_id), int(d)])
            rng = np.random.default_rng(ss)
            perm = rng.permutation(num_stocks)
            # Runtime assertion: shared row perm
            x = features_t[d].clone()
            x_permuted = x[perm]                          # full panel row-permute
            x[:, grp_indices_t] = x_permuted[:, grp_indices_t]   # only group cols replaced
            # Sanity check: non-group cols unchanged
            non_group_idx = [i for i in range(num_features) if i not in grp_indices]
            assert torch.allclose(x[:, non_group_idx], features_t[d, :, non_group_idx]), \
                "non-group features must NOT be permuted"
            x = x.to(DEVICE)
            permuted_preds[i] = model(x, full_ei).cpu().numpy()
            # Audit: store INPUT TRIPLE (truth source) + decorative metadata + spot-check
            audit_perm.append({
                'cell_id': int(cell_id),           # globally unique 0..29 — replay PRIMARY
                'arch': arch_label,                # decorative (SAGE / MLP)
                'fold_idx': int(fold_idx),         # decorative
                'seed_idx': int(seed_idx),         # decorative (0..2)
                'cell_seed_value': int(cell_seed), # decorative (86/123/456)
                'group_id': int(group_id),         # replay PRIMARY
                'group_label': group['label'],     # decorative
                'date': int(d),                    # replay PRIMARY
                'perm_first10': perm[:10].tolist() # spot-check, NOT full record
            })
    return permuted_preds, audit_perm
```

**Reproducibility (per Codex A-08 + stop-hook 2nd/5th/6th pass)**:
- **Stable group_id assignment**: `groups_168.json` MUST include a `group_id` (integer 0..K-1) field per group. Never use `hash(group_label)` in seed derivation.
- **Globally unique cell_id assignment (NEW per 6th pass)**: cell_id = arch_idx*15 + fold_idx*3 + seed_idx, range 0..29. NOT the cell_seed value 86/123/456 (which aliases across architectures and folds).
- **Seed mechanism (FULL ENTROPY, no truncation — fixed per stop-hook 5th pass)**:
  - Use `np.random.default_rng(SeedSequence([int(cell_id), int(group_id), int(date)]))` directly.
  - `SeedSequence` SHA256-mixes its inputs into PCG64's full 128-bit state — no uint32 truncation.
  - All three inputs are Python `int`, globally unique per record.
  - Numpy's `SeedSequence` + `PCG64` stability is documented across NumPy 1.17+ Generator API.
- **No Python builtin `hash()` anywhere** in the seed derivation.
- **Audit trail (carefully scoped — Codex stop-hook 4th/5th/6th pass caught successive overclaims)**:
  - **Primary reproducibility source**: the **input triple** `(cell_id, group_id, date)` stored per record. cell_id is globally unique 0..29 → triple is globally unique across all 30 × K × N_dates records → audit uniqueness assertion holds. Replay: `SeedSequence([cell_id, group_id, date])` → `default_rng` → `.permutation(num_stocks)` deterministically regenerates the same perm array, given same NumPy major version.
  - **Spot-check field (NOT full record)**: `perm_first10` = the first 10 values of `perm` per record.
  - **What this audit can prove**: (a) the seed schedule was deterministically derived from a globally unique stored triple; (b) the first 10 perm values match between runs for any record; (c) cross-version replay can recompute full perms from triples; (d) no two records have identical triples (assert during write — now actually enforceable since cell_id is unique).
  - **What this audit cannot prove**: (a) full permutation arrays match byte-for-byte (regenerate from triple to verify); (b) downstream model output reproducibility (MPS fp32 non-deterministic).
  - **Artifact file**: `artifacts/plan_aaa/audit/permutations.parquet` columns = `[cell_id, arch, fold_idx, seed_idx, cell_seed_value, group_id, group_label, date, perm_first10]`. **No `rng_seed` column**. Decorative columns (arch, fold_idx, seed_idx, cell_seed_value, group_label) are NOT used in replay — only the triple `(cell_id, group_id, date)` is needed.
  - **Replay protocol**: load row → reconstruct `SeedSequence([cell_id, group_id, date])` → `default_rng(ss).permutation(num_stocks)` → assert `regen_perm[:10].tolist() == row.perm_first10`. Pass = audit-level replay confirmed; failure = NumPy version mismatch or storage corruption.
  - **Uniqueness assertion at write time**: `assert len({(r['cell_id'], r['group_id'], r['date']) for r in audit_perm}) == len(audit_perm)`. If this fails, halt with error (no two records may share a triple — would indicate cell_id assignment bug).
- **Reproducibility scope** (carefully bounded — Codex stop-hook 3rd pass caught earlier overclaim of byte-for-byte downstream replay):
  - **Bit-exact across runs** (guaranteed): the permutation **index array** itself, given the same `(cell_id, group_id, date)` triple (cell_id globally unique 0..29 per 6th-pass fix), the same NumPy major version, and the same Python integer arithmetic. `SeedSequence` + PCG64 BitGenerator + `Generator.permutation` are deterministic on integer inputs per NumPy's stability policy for the new Generator API (numpy >= 1.17).
  - **NOT bit-exact across runs** (acknowledged): downstream `permuted_preds` (model forward pass output) and resulting `daily_ΔIC` values are subject to floating-point non-determinism in PyTorch MPS / CUDA backends — atomic-add ordering in matmul / softmax, fp32 summation order, kernel launch order. Expected ulp drift: ~1e-6 to ~1e-5 in per-prediction scores; per-day IC values typically reproducible to ~3 decimal places. Rank-based metrics (Spearman IC) are more robust than absolute values but can still flip on tie-adjacent predictions.
  - **Cross-version caveat**: a major NumPy version change (e.g., default BitGenerator changing from PCG64 to PCG64DXSM in a future NumPy 3.x) would invalidate index-array reproducibility. Save NumPy version + PyTorch version + MPS device version to `audit/environment.json` for cross-version replay accountability.
  - **What this means for paper claims**: do not claim "Plan AAA results are byte-for-byte reproducible". Do claim "Plan AAA permutation indices and seeds are reproducibly logged; downstream IC values are reproducible to MPS fp32 precision (~1e-5 ulp). Re-running on the same NumPy/PyTorch/MPS combination reproduces results to within numerical noise."
- **Runtime assertion** (NEW): at start of every Plan AAA run, assert `groups_168.json` has a `group_id` field per group AND that `group_id` values are 0..K-1 contiguous. Halt with error otherwise.

**Baseline IC** (per Codex A-05 fix + clarification):
- Computed ONCE per (model, fold, seed) cell: baseline daily IC = forward pass with non-permuted features on test_days.
- Used to compute ΔIC_{cell, group, date} = baseline_IC_{cell, date} − permuted_IC_{cell, group, date}.

### 3.4 Step 4: Aggregate Δ-IC + Ranking (FIXED A-04 + A-07)

**Aggregation order (CRITICAL fix per Codex A-04)**:

```
Step 4a: Per cell × group × date: ΔIC_{cell, grp, date} = baseline_IC_{cell, date} - permuted_IC_{cell, grp, date}
Step 4b: Per group × date: daily_ΔIC_{grp, date} = mean over 30 cells of ΔIC_{cell, grp, date}
Step 4c: Per group: NW-HAC over the DATE dimension on daily_ΔIC_{grp, ·} series
         (NOT on cell-collapsed scalars!)
Step 4d: Multiple-testing correction across K groups via BH-FDR at q=0.05
```

**Statistical pre-specification (per Codex A-07)**:
- Primary test family: all K groups in `groups_168.json` (K ≈ 30-50 estimated)
- FDR method: Benjamini-Hochberg at q=0.05
- HAC lag: `floor(4 × (T/100)^(2/9))` with T = number of test dates pooled across 5 folds (≈ 350 days) — Newey-West 1994 automatic rule
- Bootstrap CI for ΔIC: stationary block bootstrap over dates with block mean = 21 trading days (matches `analyze_tier1_phase_a.py`)
- Effect size primary metric: mean ΔIC across days
- Sign convention: ΔIC > 0 means permuting this group HURT prediction (group is important); ΔIC < 0 means permuting helped (group is harmful or noise)
